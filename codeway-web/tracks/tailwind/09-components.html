المكوّنات وأفضل الممارسات

كيف تنظّم أصنافاً كثيرة، وتبني مكوّنات قابلة لإعادة الاستخدام، وتتجنّب فوضى الترميز.

45 دقيقة مسار Tailwind CSS 5 أسئلة 1 تمرين

ماذا ستتعلّم في هذا الدرس؟

  • ترتّب الأصناف بمنطق ثابت.
  • تبني مكوّنات بمتغيّرات (variants) منظّمة.
  • تستخدم أدوات دمج الأصناف.
  • تتجنّب أخطاء شائعة تكسر Tailwind.
  • تحسّن حجم الناتج وأداء المشروع.

مشكلة السطر الطويل

أول ما يزعج في Tailwind: سطر بعشرين صنفاً. لكن المشكلة الحقيقية ليست الطول بل الفوضى: كل مطوّر يرتّبها بطريقته فيصعب المسح البصري والمقارنة.

الحل: ترتيب آليbash
npm install -D prettier prettier-plugin-tailwindcss
.prettierrcjson
{
  "plugins": ["prettier-plugin-tailwindcss"]
}
✗ خطأ
html
<div class="text-white p-4 flex bg-sky-600 rounded-lg items-center hover:bg-sky-700 gap-2 font-bold">
ترتيب عشوائي: تبحث عن اللون بين الأصناف بلا منطق.
✓ صواب
html
<div class="flex items-center gap-2 rounded-lg bg-sky-600 p-4 font-bold text-white hover:bg-sky-700">
ترتيب موحّد يفرضه الملحق آلياً: التخطيط ← المسافات ← المظهر ← النص ← الحالات.
نصيحة

ثبّت هذا الملحق في أول يوم. يرتّب الأصناف عند كل حفظ، فتتوقّف نقاشات الفريق حول الترتيب تماماً.

المكوّن هو وحدة إعادة الاستخدام

لا تكرّر عشرين صنفاً في عشرة أماكن. أنشئ مكوّناً — هذا هو الحل الصحيح لا @apply.

Reactjsx
export function Button({ variant = 'primary', size = 'md', className = '', ...props }) {
  const base = 'inline-flex items-center justify-center gap-2 rounded-lg font-bold transition focus-visible:outline-2 focus-visible:outline-offset-2 disabled:opacity-50 disabled:cursor-not-allowed';

  const variants = {
    primary: 'bg-sky-600 text-white hover:bg-sky-700',
    ghost:   'border-2 border-sky-600 text-sky-600 hover:bg-sky-50',
    danger:  'bg-rose-600 text-white hover:bg-rose-700'
  };

  const sizes = {
    sm: 'px-3 py-1.5 text-sm',
    md: 'px-5 py-2.5',
    lg: 'px-7 py-3.5 text-lg'
  };

  return (
    <button
      className={`${base} ${variants[variant]} ${sizes[size]} ${className}`}
      {...props}
    />
  );
}

أدوات الدمج

bash
npm install clsx tailwind-merge
lib/cn.tsts
import { clsx, type ClassValue } from 'clsx';
import { twMerge } from 'tailwind-merge';

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}

لماذا نحتاج أداتين؟ لأن كلاً منهما تحلّ مشكلة مختلفة:

ts
// clsx: الدمج الشرطي
cn('p-4', isActive && 'bg-sky-600', isBig ? 'text-xl' : 'text-base')

// twMerge: حلّ التعارض — الأخير يفوز
cn('p-4', 'p-8')                    // → 'p-8'
cn('bg-red-500', 'bg-blue-500')     // → 'bg-blue-500'
cn('px-4 py-2', 'p-6')              // → 'p-6'
المشكلة التي يحلّها twMerge

كتابة class="p-4 p-8" تجعل الفائز هو الأخير في ملف CSS المولَّد لا الأخير في الترميز. فقد تكتب p-8 وتحصل على p-4! twMerge يحذف المتعارض ويُبقي الأخير فعلاً.

مكوّن يقبل التخصيص بأمانjsx
import { cn } from '@/lib/cn';

export function Card({ className, ...props }) {
  return (
    <div
      className={cn(
        'rounded-2xl border border-slate-200 bg-white p-6 shadow-sm',
        className
      )}
      {...props}
    />
  );
}

<Card className="p-10 bg-sky-50">…</Card>

إدارة المتغيّرات بـ CVA

bash
npm install class-variance-authority
ts
import { cva, type VariantProps } from 'class-variance-authority';
import { cn } from '@/lib/cn';

const button = cva(
  'inline-flex items-center justify-center gap-2 rounded-lg font-bold transition focus-visible:outline-2 focus-visible:outline-offset-2 disabled:opacity-50',
  {
    variants: {
      variant: {
        primary: 'bg-sky-600 text-white hover:bg-sky-700',
        ghost:   'border-2 border-sky-600 text-sky-600 hover:bg-sky-50',
        danger:  'bg-rose-600 text-white hover:bg-rose-700'
      },
      size: {
        sm: 'px-3 py-1.5 text-sm',
        md: 'px-5 py-2.5',
        lg: 'px-7 py-3.5 text-lg'
      },
      block: {
        true: 'w-full'
      }
    },
    compoundVariants: [
      { variant: 'ghost', size: 'lg', class: 'border-4' }
    ],
    defaultVariants: { variant: 'primary', size: 'md' }
  }
);

type ButtonProps = React.ButtonHTMLAttributes<HTMLButtonElement>
  & VariantProps<typeof button>;

export function Button({ variant, size, block, className, ...props }: ButtonProps) {
  return (
    <button
      className={cn(button({ variant, size, block }), className)}
      {...props}
    />
  );
}
نصيحة

CVA يعطيك أنواعاً آمنة تلقائياً: <Button variant="primry"> سيعطي خطأ ترجمة في TypeScript. هذا وحده يستحق التبنّي في أي مشروع جادّ.

خطأ يكسر Tailwind تماماً

لا تبنِ أسماء الأصناف ديناميكياً

Tailwind يفحص ملفاتك كنصّ ويبحث عن أسماء أصناف كاملة. لا يشغّل كودك ولا يفهم تسلسل النصوص. أي اسم مبني ديناميكياً لن يُولَّد إطلاقاً.

✗ خطأ
jsx
// ✗ لن يعمل
const color = "sky";
<div className={`bg-${color}-500`} />

// ✗ ولا هذا
<div className={`text-${size}`} />

// ✗ ولا هذا
<div className={"p-" + spacing} />
Tailwind لا يرى bg-sky-500 في الملف، فلا يولّدها، فلا يوجد الصنف في CSS.
✓ صواب
jsx
// ✓ خريطة بأسماء كاملة
const colors = {
  sky: "bg-sky-500",
  rose: "bg-rose-500",
  emerald: "bg-emerald-500"
};
<div className={colors[color]} />

// ✓ أو شرط صريح
<div className={isActive ? "bg-sky-500" : "bg-slate-300"} />
الأسماء الكاملة موجودة في الملف، فيراها الفاحص ويولّدها.
معلومة

إن اضطررت لأسماء ديناميكية (من قاعدة بيانات مثلاً)، أضفها إلى قائمة @source inline(…) في CSS كي يعرف Tailwind بوجودها.

متى تكتب CSS مخصّصة؟

Tailwind لا تمنعك من CSS. هناك حالات تكون فيها CSS المخصّصة هي الأصح:

  • حركات معقّدة بعدة إطارات مفتاحية.
  • تنسيق محتوى خارجي من محرّر نصوص أو Markdown (أو استخدم إضافة typography).
  • خصائص نادرة لا تغطّيها Tailwind.
  • تنسيق شريط التمرير أو عناصر المتصفح الداخلية.
  • أنماط الطباعة المعقّدة.
css
@layer components {
  .custom-scrollbar {
    scrollbar-width: thin;
    scrollbar-color: var(--color-slate-400) transparent;
  }

  .custom-scrollbar::-webkit-scrollbar {
    width: 8px;
  }

  .custom-scrollbar::-webkit-scrollbar-thumb {
    background: var(--color-slate-400);
    border-radius: 999px;
  }
}

تحسين الناتج

  • الفحص التلقائي: Tailwind 4 يكتشف ملفاتك تلقائياً ويتجاهل .gitignore — نادراً ما تحتاج إعداداً.
  • لا تستورد كل شيء: @import "tailwindcss" تشمل ما تحتاجه فقط بعد الفحص.
  • احذف الأصناف غير المستخدمة من الترميز نفسه — لا تُبقِ كوداً معطّلاً بالتعليق.
  • راقب الحجم: npm run build ثم قِس الملف الناتج مضغوطاً.
  • تجنّب @apply المفرط: كل قاعدة تضيف حجماً ثابتاً لا يُعاد استخدامه.
bash
# البناء وقياس الحجم
npx @tailwindcss/cli -i src/style.css -o dist/style.css --minify
gzip -c dist/style.css | wc -c

قائمة أفضل الممارسات

  1. ثبّت prettier-plugin-tailwindcss من اليوم الأول.
  2. استخدم المكوّنات لإعادة الاستخدام لا @apply.
  3. استخدم cn() (clsx + tailwind-merge) في كل مكوّن يقبل className.
  4. استخدم CVA للمكوّنات ذات المتغيّرات المتعدّدة.
  5. لا تبنِ أسماء أصناف ديناميكياً أبداً.
  6. استخدم الاتجاهات المنطقية (ps/pe/start/end) في المشاريع العربية.
  7. ابدأ بالجوال ثم أضف نقاط التوقف.
  8. احترم motion-reduce في كل حركة.
  9. استخدم focus-visible لا focus لمؤشّر التركيز.
  10. خصّص الثيم في @theme بدل نثر القيم العشوائية.

تمرين: مكتبة مكوّنات

ابنِ خمسة مكوّنات قابلة لإعادة الاستخدام بأفضل الممارسات.

المطلوب:

  • دالة cn() تجمع clsx و tailwind-merge.
  • Button بـ CVA: ثلاثة أنماط، ثلاثة أحجام، وخيار block.
  • Card مركّب: Card و CardHeader و CardBody و CardFooter.
  • Badge بخمسة ألوان دلالية وحجمين.
  • Input مع حالة خطأ ورسالة، وتسمية مرتبطة.
  • Alert بأربعة أنواع وأيقونة وزر إغلاق اختياري.
  • كل مكوّن يقبل className ويدمجه بـ cn().
  • كل مكوّن يدعم الوضع الليلي.
  • كل مكوّن تفاعلي له focus-visible.
  • لا اسم صنف مبني ديناميكياً في أي مكان.
  • ثبّت prettier-plugin-tailwindcss وشغّله على المشروع.

تلميحات:

  • 💡 CVA يعطيك أنواعاً آمنة عبر VariantProps.
  • 💡 cn() تحلّ تعارض p-6 مع p-10 القادمة من className.
  • 💡 استخدم خريطة أصناف كاملة لا بناء نصّي.

/* ===== components/ui/Input.tsx ===== */
export function Input({ label, error, id, className, ...props }) {
  return (
    <div className="space-y-1.5">
      <label htmlFor={id} className="block font-semibold text-slate-700 dark:text-slate-200">
        {label}
      </label>

      <input
        id={id}
        aria-invalid={!!error}
        aria-describedby={error ? `${id}-error` : undefined}
        className={cn(
          'w-full rounded-lg border px-4 py-2.5 transition',
          'border-slate-300 focus:border-sky-500 focus:ring-2 focus:ring-sky-200',
          'dark:border-slate-600 dark:bg-slate-900',
          error && 'border-rose-500 focus:border-rose-500 focus:ring-rose-200',
          className
        )}
        {...props}
      />

      {error && (
        <p id={`${id}-error`} className="text-sm text-rose-600">
          {error}
        </p>
      )}
    </div>
  );
}

const alertIcons = {
  info: 'ℹ️',
  success: '✅',
  warning: '⚠️',
  danger: '⛔'
};

export function Alert({ tone = 'info', onClose, className, children, ...props }) {
  return (
    <div role="alert" className={cn(alert({ tone }), className)} {...props}>
      <span aria-hidden="true">{alertIcons[tone]}</span>
      <div className="flex-1">{children}</div>

      {onClose && (

          onClick={onClose}
          className="rounded p-1 transition hover:bg-black/5 focus-visible:outline-2"

  );
}

اختبر فهمك

1. لماذا لا يعمل ` className={bg-${color}-500} `؟

الشرح: الفاحص نصّي بحت؛ الاسم المبني وقت التشغيل غير موجود في الملف فلا يُولَّد.

2. ما المشكلة التي يحلّها tailwind-merge؟

الشرح: الفائز يحدّده ترتيب CSS المولَّد لا ترتيب الترميز؛ twMerge يحسمها.

3. ما البديل الصحيح لـ @apply في مشروع React؟

الشرح: المكوّن هو وحدة إعادة الاستخدام الطبيعية في أطر المكوّنات.

4. ما فائدة CVA؟

الشرح: يجمع تعريف الأنماط والأنواع في مكان واحد ويمنع الأخطاء المطبعية.

5. ما أول أداة تثبّتها في مشروع Tailwind؟

الشرح: الترتيب الموحّد يجعل الأسطر الطويلة مقروءة وينهي نقاشات الفريق.
