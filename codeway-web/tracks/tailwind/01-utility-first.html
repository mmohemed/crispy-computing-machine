فلسفة Utility-First والإعداد

لماذا تُكتب الأنماط في الترميز نفسه، والاعتراضات الشائعة والردّ عليها، وكيف تبدأ مشروعك.

40 دقيقة مسار Tailwind CSS 5 أسئلة 1 تمرين

ماذا ستتعلّم في هذا الدرس؟

  • تشرح منهجية Utility-First والمشكلة التي تحلّها.
  • تردّ على الاعتراضات الشائعة عليها بفهم.
  • تثبّت Tailwind وتشغّله في مشروعك.
  • تقرأ أسماء الأصناف وتفهم نمط تسميتها.
  • تعرف متى تكون Tailwind خياراً مناسباً ومتى لا.

المشكلة: تسمية كل شيء

في CSS التقليدية تكتب صنفاً لكل مكوّن. تبدو فكرة نظيفة حتى تواجه الواقع: ماذا تسمّي هذا الصندوق؟ .card؟ لكن هناك .card أخرى مختلفة. .product-card؟ وماذا عن نسخته في الشريط الجانبي؟ .sidebar-product-card؟

تقضي وقتاً في تسمية أشياء لا تحتاج أسماء، وتتراكم لديك أصناف يُستخدم كل منها مرة واحدة، ولا تجرؤ على حذف أي صنف خشية أن يكون مستخدماً في مكان ما.

✗ خطأ
html
<div class="product-card">
  <h3 class="product-card__title">سماعة</h3>
  <p class="product-card__price">299 ريالاً</p>
</div>

<!-- وفي ملف CSS منفصل: 20 سطراً -->
ملفان تنتقل بينهما، وثلاثة أسماء اخترعتها، وCSS ينمو مع كل مكوّن جديد.
✓ صواب
html
<div class="rounded-xl border border-slate-200 p-5">
  <h3 class="text-lg font-bold">سماعة</h3>
  <p class="text-indigo-600 font-extrabold">299 ريالاً</p>
</div>

<!-- لا ملف CSS إضافي إطلاقاً -->
كل شيء أمامك، لا أسماء تخترعها، وCSS لا ينمو مع المشروع.

ما هي Tailwind؟

إطار CSS يعطيك آلاف الأصناف المساعدة الصغيرة، كل صنف يفعل شيئاً واحداً: p-4 تضيف حشواً، flex تجعل العنصر مرناً، text-center توسّط النص. تركّب التصميم من هذه اللبنات مباشرة في الترميز.

صنف واحد = خاصية واحدة
ليست Bootstrap

Bootstrap يعطيك مكوّنات جاهزة (.btn, .card) فتبدو كل المواقع متشابهة. Tailwind يعطيك لبنات تبني بها تصميمك الخاص — فلا يوجد «شكل Tailwind».

الاعتراضات الشائعة

«الترميز يصبح قبيحاً»

html
<button class="inline-flex items-center gap-2 rounded-lg bg-indigo-600 px-5 py-3 font-bold text-white transition hover:bg-indigo-700 focus-visible:outline-2 focus-visible:outline-offset-2 disabled:opacity-50">
  إرسال
</button>

نعم، السطر طويل. لكن اسأل: كم مرة تقرأ هذا السطر مقابل كم مرة تنتقل بين ملفين لتفهم مكوّناً؟ ومع المكوّنات (React أو Vue أو Angular) تكتبه مرة واحدة وتعيد استخدام المكوّن.

«هذا مثل style= المضمّن»

الوجهstyle= مضمّنTailwind
القيمأي قيمة عشوائيةمن نظام تصميم محدود ومتّسق
الحالات (hover)مستحيلةمدعومة
التجاوبمستحيلمدعوم بالبادئات
الوضع الليليمستحيلمدعوم
الحجميتكرّر كاملاًصنف واحد يُعاد استخدامه

الفرق الجوهري: style="padding: 13px" تقبل أي رقم عشوائي، أما p-3 فتأتي من مقياس محدّد. هذا القيد هو ما يجعل التصميم متّسقاً.

«حجم الملف سيكون ضخماً»

Tailwind يفحص ملفاتك ويولّد الأصناف المستخدمة فقط. مشروع متوسط ينتج عادةً 10–20 كيلوبايت مضغوطة — أصغر من معظم ملفات CSS المكتوبة يدوياً، لأن CSS التقليدية تنمو مع كل مكوّن بينما Tailwind تتوقّف عن النمو.

نمو حجم CSS مع المشروع

التثبيت

مع Vite (الأسهل)bash
npm create vite@latest my-app
cd my-app

npm install -D tailwindcss @tailwindcss/vite
vite.config.jsjs
import { defineConfig } from 'vite';
import tailwindcss from '@tailwindcss/vite';

export default defineConfig({
  plugins: [tailwindcss()]
});
src/style.csscss
@import "tailwindcss";
بلا أداة بناء — واجهة سطر الأوامرbash
npm install -D tailwindcss @tailwindcss/cli

# المراقبة أثناء التطوير
npx @tailwindcss/cli -i src/input.css -o dist/output.css --watch

# البناء للإنتاج
npx @tailwindcss/cli -i src/input.css -o dist/output.css --minify
معلومة

الإصدار الرابع بسّط الإعداد كثيراً: لا ملف tailwind.config.js إلزامي، ولا postcss.config.js. سطر @import "tailwindcss" واحد يكفي، والتخصيص يتم في CSS نفسها.

لا تستخدم رابط CDN في الإنتاج

رابط CDN مفيد للتجربة السريعة فقط: يحمّل المكتبة كاملة (أكثر من 3 ميجابايت) ويولّد الأصناف في المتصفح. للإنتاج استخدم خطوة بناء دائماً.

التسمية منهجية ومتوقّعة، فما إن تفهم النمط حتى تخمّن الأصناف بلا رجوع للتوثيق.

متى تستخدم Tailwind؟

مناسبة حينقد لا تناسب حين
تبني بأطر مكوّنات (React/Vue/Angular)مشروع HTML ثابت صغير جداً
تريد تصميماً مخصّصاً لا قالباً جاهزاًتريد مكوّنات جاهزة فوراً بلا تصميم
فريق يحتاج اتّساقاً بلا نقاش مستمرالفريق يرفض الأصناف في الترميز
تكره اختراع الأسماءتحتاج دعم متصفحات قديمة جداً
تريد سرعة في النماذج الأوليةلا تستطيع إضافة خطوة بناء
تحتاج CSS أولاً

Tailwind ليست بديلاً عن تعلّم CSS. flex-1 لن تفيدك إن كنت لا تفهم Flexbox، وgrid-cols-3 بلا معنى إن لم تفهم Grid. Tailwind تسرّع من يعرف CSS.

تمرين: أول صفحة بـ Tailwind

جهّز مشروعاً وابنِ صفحة بسيطة بأصناف Tailwind فقط.

المطلوب:

  • أنشئ مشروع Vite وثبّت Tailwind وشغّله.
  • صفحة فيها ترويسة بخلفية ملوّنة وعنوان أبيض في المنتصف.
  • ثلاث بطاقات متجاورة، كل بطاقة: حدود، حواف دائرية، حشو، ظل، عنوان، فقرة، وزر.
  • الأزرار تغيّر لونها عند مرور المؤشّر.
  • استخدم flex و gap لترتيب البطاقات.
  • استخدم مقياس المسافات فقط — لا قيم عشوائية.
  • لا تكتب سطر CSS مخصّصاً واحداً.
  • ابنِ للإنتاج وقس حجم ملف CSS الناتج.

تلميحات:

  • 💡 تذكّر: الرقم × 4 = بكسل.
  • 💡 flex gap-4 لترتيب أفقي بمسافات.
  • 💡 transition ضرورية لتنعيم تغيّر اللون عند hover.

اختبر فهمك

1. ما الفرق الجوهري بين Tailwind و style= المضمّن؟

الشرح: القيود المتّسقة ودعم hover و md و dark هي ما يستحيل في الأنماط المضمّنة.

2. لماذا لا ينمو حجم CSS كثيراً مع Tailwind؟

الشرح: CSS التقليدية تنمو مع كل مكوّن؛ Tailwind تتوقّف عن النمو بعد تغطية الأساسيات.

3. كم بكسل يساوي الصنف p-6؟

الشرح: القاعدة: الرقم × 4 = بكسل، فـ 6 × 4 = 24 بكسل.

4. ما الفرق بين Tailwind و Bootstrap؟

الشرح: لهذا تتشابه مواقع Bootstrap، بينما لا يوجد «شكل Tailwind».

5. متى لا تكون Tailwind خياراً مناسباً؟

الشرح: تحتاج خطوة بناء، ولا تعطيك مكوّنات مصمّمة جاهزة.
