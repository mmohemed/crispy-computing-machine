مقدمة في Sass والإعداد

ما هو معالج CSS ولماذا تحتاجه، والفرق بين SCSS و Sass، وكيف تشغّله في مشروعك.

ماذا ستتعلّم في هذا الدرس؟

  • تشرح ما هو معالج CSS ولماذا وُجد.
  • تفرّق بين صيغتَي SCSS و Sass.
  • تثبّت Sass وتشغّل المترجم.
  • تفهم علاقة ملف المصدر بملف الناتج.
  • تربط الناتج بصفحتك بشكل صحيح.

ما المشكلة؟

CSS لغة ممتازة لكنها صُمّمت للبساطة. في مشروع من عشرة آلاف سطر تظهر آلامها بوضوح:

  • تكرار القيم: تكتب #6366f1 في أربعين مكاناً، ثم يطلب العميل تغيير اللون.
  • تكرار المحدّدات: .card .header .title و .card .header .subtitle و…
  • لا دوال: تحسب الظلال والتدرّجات يدوياً في كل مرة.
  • ملف واحد ضخم: أو ملفات كثيرة تعني طلبات كثيرة.
  • لا منطق: توليد 12 صنف شبكة يعني كتابة 12 قاعدة يدوياً.

Sass يحلّ هذا: لغة فوق CSS تضيف المتغيّرات والدوال والتداخل والمنطق، ثم تُترجَم إلى CSS عادية يفهمها كل متصفح.

من Sass إلى CSS

ما الذي يضيفه Sass؟

المتغيّرات

خزّن الألوان والمسافات والخطوط في أسماء واضحة وغيّرها من مكان واحد.

التداخل

اكتب المحدّدات متداخلة كما تتداخل عناصر HTML — أوضح وأقصر.

الـ Mixins

كتل قابلة لإعادة الاستخدام تقبل معاملات، مثل الدوال.

التقسيم

قسّم أنماطك إلى ملفات صغيرة تُدمَج في ملف واحد عند الترجمة.

المنطق

شروط وحلقات لتوليد الأنماط المتكرّرة آلياً.

الدوال

دوال جاهزة للألوان والرياضيات والنصوص والقوائم.

ماذا عن متغيّرات CSS الأصلية؟

CSS الحديثة فيها متغيّرات (--color) وهي رائعة لأنها تعمل وقت التشغيل فتصلح للثيمات. لكن Sass يعمل وقت البناء ويقدّم ما لا تقدّمه CSS: الحلقات والشروط والدوال والتقسيم. الاثنان يكمّلان بعضهما، ولا يلغي أحدهما الآخر.

SCSS أم Sass؟

للغة صيغتان مختلفتان في الشكل ومتطابقتان في القدرات:

نصيحة

استخدم SCSS. ميزته الحاسمة أنك تستطيع نسخ أي كود CSS ولصقه كما هو فيعمل مباشرة — فالانتقال تدريجي بلا ألم. هذا المسار كله يستخدم SCSS.

التثبيت والتشغيل

داخل مشروعكbash
# 1) تهيئة المشروع إن لم يكن مهيّأً
npm init -y

# 2) تثبيت Sass كاعتمادية تطوير
npm install --save-dev sass

# 3) ترجمة مرة واحدة
npx sass src/scss/main.scss dist/css/style.css

# 4) المراقبة: يعيد الترجمة عند كل حفظ
npx sass --watch src/scss:dist/css

# 5) نسخة مضغوطة للإنتاج
npx sass src/scss/main.scss dist/css/style.min.css --style=compressed --no-source-map
package.json — اختصر الأوامرjson
{
  "scripts": {
    "css": "sass src/scss:dist/css",
    "css:watch": "sass --watch src/scss:dist/css",
    "css:build": "sass src/scss/main.scss dist/css/style.css --style=compressed --no-source-map"
  }
}

ثم تشغّلها بـ npm run css:watch أثناء التطوير و npm run css:build قبل النشر.

معلومة

أدوات البناء الحديثة (Vite و Next.js و Angular CLI) تدعم Sass تلقائياً: يكفي تثبيت الحزمة واستيراد ملف .scss، وتتكفّل الأداة بالترجمة.

الربط بالصفحة

اربط الناتج لا المصدر

المتصفح لا يفهم .scss إطلاقاً. الرابط يجب أن يشير دائماً إلى ملف .css المولَّد.

✗ خطأ
html
<link rel="stylesheet" href="src/scss/main.scss">
المتصفح سيحمّل ملفاً نصياً لا يفهمه، فلن يُطبَّق أي تنسيق.
✓ صواب
html
<link rel="stylesheet" href="dist/css/style.css">
الملف المترجَم هو ما يفهمه المتصفح.

ما معنى الشرطة السفلية؟

الملف الذي يبدأ اسمه بـ _ يُسمّى جزئياً (Partial): لا يُترجَم إلى ملف CSS مستقل، بل يُستورد داخل ملف آخر. هذا يمنع توليد عشرات الملفات غير المرغوبة.

main.scssscss
@use 'abstracts/variables';
@use 'abstracts/mixins';
@use 'base/reset';
@use 'base/typography';
@use 'layout/header';
@use 'components/button';
@use 'components/card';

لاحظ: لا تكتب الشرطة السفلية ولا الامتداد عند الاستيراد. Sass يعرفهما.

التعليقات

scss
// تعليق سطر واحد — لا يظهر في ملف CSS الناتج

/* تعليق CSS عادي — يظهر في الناتج */

/*! تعليق محفوظ — يبقى حتى في النسخة المضغوطة */
نصيحة

استخدم // لملاحظاتك التطويرية (فلا تثقل الملف النهائي)، و/ / للمعلومات التي تريد بقاءها كحقوق المكتبة.

خرائط المصدر (Source Maps)

حين تفحص عنصراً في أدوات المطوّر ستجد الأنماط في ملف .css المولَّد — وهذا لا يفيدك. خريطة المصدر تربط كل قاعدة بموضعها الأصلي في ملف .scss، فتظهر لك أدوات المطوّر «هذه القاعدة من _button.scss السطر 24».

bash
# خرائط المصدر مفعّلة افتراضياً في التطوير
npx sass --watch src/scss:dist/css

# عطّلها في الإنتاج لتقليل الحجم
npx sass src/scss/main.scss dist/css/style.css --no-source-map --style=compressed

تمرين: أول مشروع Sass

جهّز مشروعاً وشغّل المترجم وتأكّد من أن التغييرات تنعكس فوراً.

المطلوب:

  • أنشئ مجلداً جديداً وهيّئ package.json وثبّت sass كاعتمادية تطوير.
  • أنشئ src/scss/main.scss و index.html و مجلد dist/css.
  • أضف أوامر css:watch و css:build في package.json.
  • في main.scss عرّف متغيّراً واحداً للون واستخدمه في قاعدتين مختلفتين.
  • شغّل المراقبة وغيّر قيمة المتغيّر ولاحظ تحديث ملف CSS تلقائياً.
  • اربط ملف CSS المولَّد بصفحة HTML وتأكّد من ظهور التنسيق.
  • أنشئ ملفاً جزئياً _variables.scss وانقل إليه المتغيّر واستورده بـ @use.
  • شغّل أمر البناء المضغوط وقارن حجم الملفين.

تلميحات:

  • 💡 الملف الجزئي يبدأ بـ _ ولا تكتب الشرطة ولا الامتداد عند الاستيراد.
  • 💡 @use يجب أن تكون في أعلى الملف قبل أي قاعدة.
  • 💡 إن لم يعمل التنسيق تحقّق من مسار href — يجب أن يشير إلى .css.

src/scss/main.scssscss
@use 'variables' as v;

body {

  background: #f6f7fb;
  color: #0f172a;
  padding: 40px;
}

.btn {
  display: inline-block;
  padding: 12px 28px;
  border-radius: 99px;
  background: v.$brand;
  color: #fff;
  text-decoration: none;
}

.title {
  color: v.$brand;
  font-size: 2rem;
}
