مقدمة في React ولماذا المكوّنات

ما المشكلة التي حلّتها React، وما معنى «الواجهة دالة من الحالة»، ومتى تحتاجها ومتى لا.

40 دقيقة مسار React 5 أسئلة 1 تمرين

ماذا ستتعلّم في هذا الدرس؟

  • تشرح المشكلة التي وُجدت React لحلّها.
  • تفرّق بين النهج الأمري والنهج التصريحي.
  • تفهم فكرة المكوّن والـ DOM الافتراضي.
  • تعرف متى تستخدم React ومتى تكون مبالغة.
  • تميّز بين React ومكتبات وأطر أخرى.

المشكلة قبل React

تخيّل تطبيق سلّة تسوّق. عند إضافة منتج عليك يدوياً: تحديث عدّاد السلة، وإضافة صف في القائمة، وإعادة حساب الإجمالي، وتفعيل زر الدفع، وإخفاء رسالة «السلة فارغة». خمس عمليات لتغيير واحد.

النهج الأمري — تقول «كيف» خطوة بخطوةjs
function addToCart(product) {
  cart.push(product);

  document.getElementById('count').textContent = cart.length;

  const li = document.createElement('li');
  li.textContent = product.name;
  document.getElementById('list').appendChild(li);

  document.getElementById('total').textContent = calcTotal(cart);
  document.getElementById('checkout').disabled = false;
  document.getElementById('empty-msg').style.display = 'none';
}

مع نمو التطبيق يصبح تتبّع «من يحدّث ماذا ومتى» كابوساً. تنسى تحديث عنصر فتظهر بيانات قديمة، وتظهر أخطاء يصعب تتبّعها لأن الحقيقة موزّعة بين متغيّراتك والـ DOM.

الفكرة المركزية: الواجهة دالة من الحالة

React تقلب المعادلة. أنت لا تصف كيف تعدّل الواجهة، بل تصف كيف يجب أن تبدو الواجهة عند كل حالة ممكنة. ثم تغيّر الحالة فقط، وتتكفّل React بالباقي.

النهج التصريحي — تقول «ماذا» فقطjsx
function Cart({ items }) {
  const total = items.reduce((sum, item) => sum + item.price, 0);

  if (items.length === 0) {
    return <p>السلة فارغة</p>;
  }

  return (
    <div>
      <span>عدد المنتجات: {items.length}</span>
      <ul>
        {items.map(item => <li key={item.id}>{item.name}</li>)}
      </ul>
      <strong>الإجمالي: {total} ريالاً</strong>
      <button>إتمام الشراء</button>
    </div>
  );
}

أضف عنصراً إلى items وستتحدّث كل هذه الأجزاء تلقائياً. لا getElementById، ولا تتبّع يدوي، ولا نسيان.

المعادلة التي تلخّص React

UI = f(state) — الواجهة نتيجة دالة تأخذ الحالة. غيّر المدخلات فتتغيّر المخرجات. هذا كل شيء.

ما هو المكوّن؟

المكوّن (Component) هو دالة جافاسكربت تُرجع واجهة. تبني تطبيقك من مكوّنات صغيرة تتركّب فوق بعضها، تماماً كما تبني صفحة HTML من عناصر.

jsx
function Badge({ text }) {
  return <span className="badge">{text}</span>;
}

function ProductCard({ product }) {
  return (
    <article className="card">
      <img src={product.image} alt={product.name} />
      <h3>{product.name}</h3>
      <Badge text={product.category} />
      <p>{product.price} ريالاً</p>
    </article>
  );
}

function ProductList({ products }) {
  return (
    <div className="grid">
      {products.map(p => <ProductCard key={p.id} product={p} />)}
    </div>
  );
}
النتيجة المرسومة

لاحظ الفوائد: ProductCard يُكتب مرة ويُستخدم مئات المرات. تعديل تصميم البطاقة يتم في مكان واحد. وكل مكوّن قابل للاختبار والفهم بمعزل عن غيره.

الـ DOM الافتراضي

تعديل DOM الحقيقي عملية بطيئة نسبياً. لو أعادت React رسم كل شيء عند كل تغيير لكان التطبيق بطيئاً. الحل:

  1. تحتفظ React بنسخة خفيفة من الواجهة كأشياء جافاسكربت عادية — هذا هو الـ DOM الافتراضي.
  2. عند تغيّر الحالة، تبني نسخة جديدة كاملة (رخيصة لأنها مجرّد كائنات).
  3. تقارن الجديدة بالقديمة وتحدّد الفروق فقط (عملية تُسمّى Reconciliation).
  4. تطبّق تلك الفروق وحدها على DOM الحقيقي.

النتيجة: تكتب كأنك تعيد رسم كل شيء، وتحصل على أداء تحديث انتقائي دقيق.

نصيحة

لا تحتاج فهم آلية المقارنة بالتفصيل لتستخدم React، لكن معرفتها تفسّر لك لاحقاً لماذا المفاتيح key مهمة في القوائم ولماذا لا يجوز تعديل الحالة مباشرة.

مبدأ التدفّق أحادي الاتجاه

البيانات في React تنزل من الأب إلى الابن عبر props فقط — لا العكس. الابن لا يستطيع تعديل بيانات أبيه مباشرة، بل يستدعي دالة مرّرها له الأب.

اتجاه البيانات
معلومة

هذا القيد يبدو مزعجاً في البداية لكنه أعظم ميزة: عندما تظهر بيانات خاطئة، تعرف بالضبط أين تبحث — في المكوّن الذي يملك تلك الحالة، لا في أي مكان من التطبيق.

متى تستخدم React؟ ومتى لا؟

استخدمها حينلا تستخدمها حين
الواجهة تتغيّر كثيراً بتفاعل المستخدمالموقع محتوى ثابت بلا تفاعل يُذكر
تتكرّر نفس البنية بأشكال مختلفةصفحة واحدة بسيطة
حالة معقّدة تؤثّر في أماكن متعدّدةيكفيك سطران من جافاسكربت
فريق يعمل على أجزاء متفرّقةمدونة أو صفحة هبوط
ستبني تطبيق جوال لاحقاً (React Native)الأداء الأولي وحجم الحزمة أولوية قصوى
لا تقفز إلى React مبكراً

React تُبنى فوق JavaScript لا بدلاً منها. إن لم تتقن الدوال والمصفوفات والتفكيك والوعود، فستقاتل في معركتين معاً. أتقن الأساس أولاً.

React في المشهد العام

الأداةالنوعما يميّزها
Reactمكتبة واجهةمرنة، مجتمع ضخم، تختار بقية الأدوات بنفسك
Vueإطار تقدّميأسهل منحنى تعلّم، قوالب قريبة من HTML
Angularإطار متكاملكل شيء جاهز، مبني على TypeScript، مناسب للمؤسسات
Svelteمترجميترجم إلى JS عادية، لا وقت تشغيل تقريباً
Next.jsإطار فوق Reactالعرض من الخادم، التوجيه، وتحسين تلقائي

React مكتبة لا إطار عمل: تعطيك بناء الواجهة فقط، وتترك لك اختيار التوجيه وإدارة الحالة وطلبات الشبكة. هذه مرونة وعبء في آن واحد.

ماذا ستتعلّم في هذا المسار؟

  1. إعداد المشروع وكتابة JSX.
  2. بناء المكوّنات وتمرير props.
  3. إدارة الحالة بـ useState والتعامل مع الأحداث.
  4. العرض الشرطي والقوائم والمفاتيح.
  5. النماذج والمدخلات المتحكَّم بها.
  6. useEffect وجلب البيانات من واجهة برمجية.
  7. رفع الحالة وuseContext لتفادي تمرير props الطويل.
  8. useReducer والـ Hooks المخصّصة وتحسين الأداء.
  9. التوجيه بين الصفحات.
  10. مشروع تطبيقي متكامل.

تمرين ذهني: فكّك واجهة إلى مكوّنات

لا كود في هذا التمرين — بل تدريب على «التفكير بالمكوّنات»، وهو أهم مهارة في React.

المطلوب:

  • افتح أي موقع تعرفه (متجر، شبكة اجتماعية، منصة تعليمية).
  • ارسم مستطيلات حول كل جزء قابل لإعادة الاستخدام.
  • سمِّ كل مكوّن باسم واضح: SearchBar, ProductCard, Sidebar.
  • ارسم شجرة تبيّن أي مكوّن يحتوي أيّاً.
  • حدّد لكل مكوّن: ما البيانات التي يستقبلها (props)؟
  • حدّد أي مكوّن يجب أن يملك الحالة المشتركة.

تلميحات:

  • 💡 قاعدة المسؤولية الواحدة: إن كان المكوّن يفعل أكثر من شيء، قسّمه.
  • 💡 الحالة المشتركة تُوضع في أقرب أب مشترك للمكوّنات التي تحتاجها.
  • 💡 المكوّن الجيد يمكن وصفه بجملة واحدة.
عرض الحل المقترح
مثال: شجرة مكوّنات متجرtext
App
├── Header
│   ├── Logo
│   ├── SearchBar          props: value, onSearch
│   └── CartButton         props: itemsCount

│   └── ProductGrid        props: products
│       └── ProductCard    props: product, onAddToCart
│           ├── ProductImage

└── Footer

تُوضع في App لأنه أقرب أب مشترك بين Header و Main.
هذا التمرين يبدو بسيطاً لكنه يفصل بين من يكتب React ومن يتقنها.

اختبر فهمك

1. ما معنى «الواجهة دالة من الحالة»؟

الشرح: النهج التصريحي: تصف «ماذا» لا «كيف»، وتغيّر الحالة فقط.

2. ما وظيفة الـ DOM الافتراضي؟

الشرح: المقارنة على كائنات جافاسكربت رخيصة، فتُطبَّق الفروق فقط على DOM البطيء.

3. كيف تنتقل البيانات في React؟

الشرح: التدفّق أحادي الاتجاه؛ الابن يبلّغ الأب باستدعاء دالة مرّرها الأب له.

4. React هي…

الشرح: مكتبة تركّز على الواجهة، وتترك التوجيه وإدارة الحالة لاختيارك.

5. متى تكون React خياراً غير مناسب؟

الشرح: المحتوى الثابت يُخدَم أفضل بـ HTML بسيط: أسرع تحميلاً وأبسط صيانة.
