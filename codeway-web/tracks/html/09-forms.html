النماذج: الأساسيات

كيف تجمع بيانات من المستخدم: عناصر النموذج، التسميات، الأزرار، وطرق الإرسال.

55 دقيقة مسار HTML 5 أسئلة 1 تمرين

ماذا ستتعلّم في هذا الدرس؟

  • تبني نموذجاً كاملاً بعناصر إدخال وأزرار.
  • تربط كل حقل بتسمية <label> بشكل صحيح.
  • تفرّق بين GET و POST وتعرف متى تستخدم كلاً منهما.
  • تجمّع الحقول المترابطة بـ <fieldset> و <legend>.
  • تعرف دور السمة name ولماذا بدونها تضيع البيانات.

لماذا النماذج مهمة؟

كل تفاعل حقيقي على الويب يمرّ عبر نموذج: تسجيل الدخول، البحث، الشراء، التعليق، رفع ملف. النموذج هو الجسر الذي تعبر عليه بيانات المستخدم من المتصفح إلى الخادم.

العنصر الحاوي <form>

html
<form action="/subscribe" method="post">
  …حقول النموذج…
  <button type="submit">اشترك</button>
</form>
السمةوظيفتها
actionالعنوان الذي تُرسل إليه البيانات. إن حُذف تُرسل لنفس الصفحة.
methodget أو post — طريقة الإرسال.
enctypeترميز البيانات؛ يجب أن يكون multipart/form-data عند رفع الملفات.
novalidateتعطيل تحقّق المتصفح المدمج (للاختبار غالباً).
autocompleteon أو off للإكمال التلقائي.

الوجهGETPOST

قاعدة أمنية

لا ترسل كلمة مرور أو بيانات حسّاسة عبر GET أبداً — ستُسجَّل في سجلّ المتصفح وسجلّات الخادم ونصّ الرابط الذي قد يُشارَك.

معلومة

قاعدة عامة: استخدم GET إذا كان الطلب قراءة لا تغيّر شيئاً، و POST إذا كان يغيّر حالة على الخادم.

التسمية <label> — ليست ترفاً

التسمية تخبر المستخدم ما المطلوب في الحقل، وتخبر قارئ الشاشة كذلك. وهناك فائدة عملية إضافية: النقر على التسمية ينقل التركيز إلى الحقل — وهذا يوسّع مساحة النقر كثيراً، خصوصاً لمربّعات الاختيار الصغيرة على الجوال.

طريقتان صحيحتانhtml
<!-- 1) الربط الصريح عبر for و id — الموصى به -->
<label for="email">البريد الإلكتروني</label>
<input type="email" id="email" name="email">

<!-- 2) الاحتواء -->
<label>
  البريد الإلكتروني
  <input type="email" name="email">
</label>
✗ خطأ
html
<p>البريد الإلكتروني</p>
<input type="email" name="email">

<input type="text" placeholder="الاسم">
لا ربط بين النص والحقل. وplaceholder ليس تسمية: يختفي عند الكتابة وتباينه اللوني ضعيف.
✓ صواب
html
<label for="email">البريد الإلكتروني</label>
<input type="email" id="email" name="email">

<label for="name">الاسم</label>
<input type="text" id="name" name="name" placeholder="مثال: محمد أحمد">
تسمية دائمة مرتبطة، وplaceholder مستخدم كما ينبغي: مثال توضيحي إضافي.
جرّب النقر على كلمة «أوافق»

السمة name: بدونها لا شيء يُرسل

عند الإرسال يجمع المتصفح أزواج name=value من كل حقل. أي حقل بلا name يُتجاهل تماماً. الفرق بين id و name:

  • id — معرّف داخل الصفحة، تستخدمه <label for> وCSS وJavaScript.
  • name — اسم الحقل عند الإرسال إلى الخادم. هو ما يقرؤه الخادم.

مثال: نموذج فيه name="q" وقيمة «html» مع method="get" يُرسل الطلب إلى /search?q=html.

أنواع الإدخال الأساسية

html
<label for="fullname">الاسم الكامل</label>
<input type="text" id="fullname" name="fullname">

<label for="mail">البريد</label>
<input type="email" id="mail" name="mail">

<label for="pass">كلمة المرور</label>
<input type="password" id="pass" name="pass">

<label for="age">العمر</label>
<input type="number" id="age" name="age" min="1" max="120">

<label for="bio">نبذة عنك</label>
<textarea id="bio" name="bio" rows="4"></textarea>
نموذج مصغّر
معلومة

<textarea> عنصر غير فارغ: قيمته الابتدائية تُكتب بين وسمَي الفتح والإغلاق، لا في سمة value. وانتبه: أي مسافة تكتبها بينهما ستظهر داخل الحقل.

المفتاح هو `name` الموحّد

أزرار الاختيار تتصرّف كمجموعة واحدة فقط إذا حملت نفس قيمة name. أما id فيجب أن يكون مختلفاً لكل زر.

مربّعات الاختيار (Checkbox) — عدة خيارات

html
<fieldset>
  <legend>اهتماماتك</legend>

  <input type="checkbox" id="i1" name="topics" value="html">
  <label for="i1">HTML</label>

  <input type="checkbox" id="i2" name="topics" value="css">
  <label for="i2">CSS</label>
</fieldset>

استخدام نفس name مع قيم مختلفة يجعل الخادم يستقبلها كمصفوفة من القيم المختارة.

التجميع بـ <fieldset> و <legend>

يجمعان الحقول المترابطة تحت عنوان واحد. هذا ليس تجميلاً: قارئ الشاشة يعلن نص <legend> قبل كل خيار داخل المجموعة، فيفهم المستخدم أن «مبتدئ» تخصّ «مستوى خبرتك».

الأزرار

html
<button type="submit">إرسال</button>
<button type="reset">إعادة تعيين</button>
<button type="button">زر بلا سلوك افتراضي</button>
فخّ شهير

قيمة type الافتراضية لـ <button> داخل نموذج هي submit. إن نسيت كتابة type="button" على زر مساعد، سيرسل النموذج عند كل نقرة عليه.

نصيحة

تجنّب type="reset" في معظم النماذج — قلّما يريده المستخدم، وكثيراً ما يُنقر بالخطأ فيمحو كل ما كتبه.

تمرين: نموذج تسجيل في دورة

ابنِ نموذج تسجيل كامل. لا حاجة لخادم — استخدم action="#" واختبر البنية فقط.

المطلوب:

  • كل حقل له <label> مرتبطة بـ for و id، وله name.
  • حقول: الاسم، البريد، رقم الجوال، تاريخ الميلاد، كلمة المرور.
  • مجموعة أزرار اختيار لمستوى الخبرة داخل <fieldset> مع <legend>.
  • مربّعات اختيار للمسارات المرغوبة (يمكن اختيار أكثر من واحد).
  • قائمة <select> مقسّمة بـ <optgroup> لاختيار المدينة.
  • مربّع اختيار للموافقة على الشروط، وزر إرسال واحد.

تلميحات:

  • 💡 أزرار الاختيار تشترك في name وتختلف في id و value.
  • 💡 الخيار الأول في <select> يُفضَّل أن يكون فارغ القيمة كتنبيه للاختيار.
  • 💡 لا تنسَ type="submit" صراحةً على زر الإرسال للوضوح.

اختبر فهمك

1. ماذا يحدث لحقل بلا سمة name عند الإرسال؟

الشرح: المتصفح يجمع أزواج name=value؛ الحقل بلا name يُتجاهل تماماً.

2. أي طريقة إرسال تستخدم لتسجيل الدخول؟

الشرح: GET يضع البيانات في شريط العنوان وسجلّات الخادم — غير مقبول لكلمات المرور.

3. كيف تجعل ثلاثة أزرار اختيار مجموعة واحدة؟

الشرح: نفس name يجعلها متنافية؛ وid يجب أن يبقى فريداً لكل زر لأجل التسمية.

4. لماذا لا يصلح placeholder بديلاً عن <label>؟

الشرح: placeholder مثال توضيحي مؤقت؛ التسمية معلومة دائمة مرتبطة بنيوياً بالحقل.

5. ما القيمة الافتراضية لسمة type في <button> داخل نموذج؟

الشرح: الافتراضي submit، لذا يجب كتابة type="button" صراحةً لأي زر لا يُراد به الإرسال.
