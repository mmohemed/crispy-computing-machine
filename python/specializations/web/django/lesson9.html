الأمان في Django

تعلم تقنيات الأمان المدمجة في Django لحماية تطبيقاتك من الثغرات الأمنية الشائعة.

مدة القراءة: 12 دقيقة مستوى: متقدم أمان حماية

لماذا الأمان مهم في Django؟

الأمان هو أحد أهم الجوانب في تطوير تطبيقات الويب. يوفر Django طبقات متعددة من الحماية المدمجة التي تساعد في حماية تطبيقك من الهجمات الأمنية الشائعة.

تشمل ميزات الأمان في Django:

  • حماية CSRF: منع هجمات التزوير عبر المواقع.
  • حماية XSS: منع هجمات البرمجة النصية عبر المواقع.
  • حماية SQL Injection: منع حقن SQL.
  • إدارة الجلسات: جلسات آمنة ومشفرة.
  • تشفير كلمات المرور: تخزين آمن لكلمات المرور.
  • الصلاحيات: التحكم في الوصول إلى الموارد.
تنبيه هام: الأمان ليس مجرد ميزة إضافية، بل هو ضرورة في أي تطبيق ويب. إهمال الأمان قد يؤدي إلى اختراق التطبيق وسرقة بيانات المستخدمين.

حماية CSRF

CSRF (Cross-Site Request Forgery) هو هجوم يحدث عندما يقوم مهاجم بخداع مستخدم موثوق لتنفيذ طلبات غير مرغوب فيها على تطبيق الويب.

كيف تحمي Django من CSRF؟

HTML Template
<form method="post">
    {% csrf_token %}
    <input type="text" name="title">
    <button type="submit">إرسال</button>
</form>
AJAX Request
// إضافة CSRF token إلى طلبات AJAX
const csrftoken = document.querySelector('[name=csrfmiddlewaretoken]').value;

fetch('/api/posts/', {
    method: 'POST',
    headers: {
        'X-CSRFToken': csrftoken,
        'Content-Type': 'application/json',
    },
    body: JSON.stringify(data)
});
ملاحظة: Django يقوم تلقائياً بالتحقق من وجود رمز CSRF صحيح في جميع طلبات POST. استخدم @csrf_exempt فقط عند الضرورة القصوى.

حماية XSS

XSS (Cross-Site Scripting) هو هجوم يقوم فيه المهاجم بحقن كود برمجي خبيث في صفحات الويب التي يشاهدها المستخدمون الآخرون.

كيف تحمي Django من XSS؟

يقوم Django تلقائياً بتشفير المحتوى المعروض في القوالب:

HTML Template
<!-- يتم تشفير المحتوى تلقائياً -->
<p>{{ user_input }}</p>

<!-- استخدام safe لعرض HTML الخام (استخدم بحذر) -->
<p>{{ user_input|safe }}</p>

<!-- استخدام escape للتحكم في التشفير -->
<p>{{ user_input|escape }}</p>
تنبيه: استخدام |safe أو autoescape off يعرض تطبيقك لخطر هجمات XSS. استخدمهما فقط مع محتوى موثوق.

حماية SQL Injection

SQL Injection هو هجوم يقوم فيه المهاجم بحقن استعلامات SQL خبيثة للوصول إلى قاعدة البيانات أو تعديلها.

كيف تحمي Django من SQL Injection؟

يقوم ORM في Django تلقائياً بحماية تطبيقك من SQL Injection:

الطريقة الآمنة (استخدم هذه)
# استخدام ORM - آمن
posts = Post.objects.filter(title__contains=user_input)

# استخدام parameters في raw SQL - آمن
posts = Post.objects.raw('SELECT * FROM blog_post WHERE title LIKE %s', [user_input])
الطريقة غير الآمنة (تجنب هذه)
# تجنب هذا - غير آمن!
posts = Post.objects.raw(f'SELECT * FROM blog_post WHERE title LIKE "{user_input}"')
نصيحة: استخدم Django ORM دائماً للتعامل مع قاعدة البيانات. ORM يقوم تلقائياً بمعالجة المدخلات وحمايتها من SQL Injection.

أفضل ممارسات الأمان

  • استخدم {% csrf_token %}: في جميع نماذج POST.
  • لا تستخدم |safe: إلا مع محتوى موثوق تماماً.
  • استخدم DEBUG=False: في بيئة الإنتاج.
  • قم بتحديث SECRET_KEY: احتفظ بها سرية ولا تشاركها.
  • استخدم ALLOWED_HOSTS: لتحديد النطاقات المسموح بها.
  • تحقق من صحة البيانات: دائماً تحقق من البيانات المدخلة من المستخدمين.
  • استخدم HTTPS: في بيئة الإنتاج لحماية البيانات أثناء النقل.
  • قم بتحديث Django بانتظام: للحصول على أحدث تصحيحات الأمان.
إعدادات الأمان الموصى بها (settings.py)
# إعدادات الأمان الأساسية
DEBUG = False
SECRET_KEY = 'your-secret-key-here'  # استخدم متغيرات البيئة
ALLOWED_HOSTS = ['yourdomain.com', 'www.yourdomain.com']

# إعدادات HTTPS
SECURE_SSL_REDIRECT = True
SESSION_COOKIE_SECURE = True
CSRF_COOKIE_SECURE = True
SECURE_HSTS_SECONDS = 31536000  # 1 سنة
SECURE_HSTS_INCLUDE_SUBDOMAINS = True
SECURE_HSTS_PRELOAD = True

# إعدادات إضافية
SECURE_BROWSER_XSS_FILTER = True
SECURE_CONTENT_TYPE_NOSNIFF = True
X_FRAME_OPTIONS = 'DENY'
