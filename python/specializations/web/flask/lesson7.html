بناء RESTful APIs

تعلم كيفية بناء واجهات برمجة تطبيقات احترافية (APIs) باستخدام Flask-RESTful و Flask-RESTx.

مدة القراءة: 16 دقيقة مستوى: متوسط JSON / REST

ما الذي سنتعلمه؟

في هذا الدرس، سنتعلم كيفية بناء واجهات برمجة تطبيقات (APIs) احترافية في Flask باستخدام Flask-RESTful و Flask-RESTx.

  • ✅ ما هي RESTful API – مفاهيم وأساسيات تصميم APIs.
  • ✅ تثبيت Flask-RESTful – إضافة المكتبة إلى المشروع.
  • ✅ إنشاء الموارد (Resources) – تعريف نقاط النهاية (Endpoints).
  • ✅ معالجة الطلبات – GET, POST, PUT, DELETE.
  • ✅ تحليل الطلبات – استخدام RequestParser لاستقبال البيانات.
  • ✅ إرجاع الاستجابات – تنسيق JSON مع رموز الحالة.
  • ✅ توثيق API – استخدام Flask-RESTx لتوثيق الـ API.

ما هي RESTful API؟

REST (Representational State Transfer) هو نمط معماري لتصميم واجهات برمجة التطبيقات. يستخدم HTTP كبروتوكول للتواصل ويعتمد على مجموعة من المبادئ.

موارد (Resources)

كل شيء في API هو مورد (مستخدم، منشور، منتج)

طرق HTTP

GET, POST, PUT, DELETE للعمليات الأساسية

JSON/XML

تنسيق البيانات المستخدم في التبادل

عديم الحالة

كل طلب مستقل ولا يحافظ على حالة سابقة

ملاحظة: RESTful APIs هي المعيار الحديث لبناء تطبيقات الويب والموبايل التي تتواصل مع الخادم.

طرق HTTP الأساسية

تستخدم APIs طرق HTTP للدلالة على نوع العملية المطلوبة:

الطريقة الوصف مثال
GET جلب البيانات /api/users → جلب جميع المستخدمين
POST إنشاء مورد جديد /api/users → إنشاء مستخدم جديد
PUT تحديث مورد كامل /api/users/1 → تحديث المستخدم 1
DELETE حذف مورد /api/users/1 → حذف المستخدم 1
PATCH تحديث جزئي /api/users/1 → تحديث جزء من المستخدم

إنشاء أول Resource

في Flask-RESTful، تُعرف الموارد (Resources) باستخدام كلاسات ترث من Resource.

app.py - موارد المستخدمين

from flask import Flask
from flask_restful import Api, Resource, reqparse, abort

app = Flask(__name__)
api = Api(app)

# بيانات وهمية
users = [
    {'id': 1, 'name': 'أحمد', 'email': 'ahmed@example.com'},
    {'id': 2, 'name': 'سارة', 'email': 'sara@example.com'},
]
next_id = 3

# معالج الطلبات
user_parser = reqparse.RequestParser()
user_parser.add_argument('name', type=str, required=True, help='الاسم مطلوب')
user_parser.add_argument('email', type=str, required=True, help='البريد الإلكتروني مطلوب')

class UserListResource(Resource):
    """الموارد لجلب جميع المستخدمين وإنشاء مستخدم جديد"""
    
    def get(self):
        """GET /api/users - جلب جميع المستخدمين"""
        return {'users': users}, 200
    
    def post(self):
        """POST /api/users - إنشاء مستخدم جديد"""
        args = user_parser.parse_args()
        
        new_user = {
            'id': next_id,
            'name': args['name'],
            'email': args['email']
        }
        users.append(new_user)
        global next_id
        next_id += 1
        
        return {'user': new_user, 'message': 'تم إنشاء المستخدم بنجاح'}, 201

class UserResource(Resource):
    """الموارد لمستخدم فردي"""
    
    def get(self, user_id):
        """GET /api/users/{id} - جلب مستخدم محدد"""
        user = next((u for u in users if u['id'] == user_id), None)
        if not user:
            abort(404, message='المستخدم غير موجود')
        return {'user': user}, 200
    
    def put(self, user_id):
        """PUT /api/users/{id} - تحديث مستخدم بالكامل"""
        user = next((u for u in users if u['id'] == user_id), None)
        if not user:
            abort(404, message='المستخدم غير موجود')
        
        args = user_parser.parse_args()
        user['name'] = args['name']
        user['email'] = args['email']
        
        return {'user': user, 'message': 'تم تحديث المستخدم بنجاح'}, 200
    
    def delete(self, user_id):
        """DELETE /api/users/{id} - حذف مستخدم"""
        global users
        user = next((u for u in users if u['id'] == user_id), None)
        if not user:
            abort(404, message='المستخدم غير موجود')
        
        users = [u for u in users if u['id'] != user_id]
        return {'message': 'تم حذف المستخدم بنجاح'}, 200

# تسجيل الموارد
api.add_resource(UserListResource, '/api/users')
api.add_resource(UserResource, '/api/users/<int:user_id>')

if __name__ == '__main__':
    app.run(debug=True)
ملاحظة: reqparse يساعد في تحليل الطلبات والتحقق من صحة البيانات المدخلة.

رموز الحالة (Status Codes)

رموز الحالة تخبر العميل بنتيجة الطلب. إليك الرموز الأكثر استخداماً:

  • 200 OK – الطلب ناجح (GET, PUT).
  • 201 Created – تم إنشاء المورد بنجاح (POST).
  • 204 No Content – الطلب ناجح ولا يوجد محتوى (DELETE).
  • 400 Bad Request – طلب غير صحيح (بيانات مفقودة أو غير صالحة).
  • 401 Unauthorized – غير مصرح (يحتاج مصادقة).
  • 403 Forbidden – ممنوع (ليس لديك صلاحية).
  • 404 Not Found – المورد غير موجود.
  • 500 Internal Server Error – خطأ في الخادم.
تذكير: استخدم رموز الحالة المناسبة لكل عملية لتحسين تجربة المطورين الذين يستخدمون الـ API.

Flask-RESTx للتوثيق المتقدم

Flask-RESTx هو نسخة متطورة من Flask-RESTful توفر توثيقاً تلقائياً باستخدام Swagger UI.

استخدام Flask-RESTx

from flask import Flask
from flask_restx import Api, Resource, fields

app = Flask(__name__)

# تهيئة API مع التوثيق
api = Api(app, 
    title='Flask API',
    description='مثال لـ API باستخدام Flask-RESTx',
    doc='/docs/'  # واجهة Swagger UI
)

# تعريف نموذج البيانات
user_model = api.model('User', {
    'id': fields.Integer(readonly=True, description='معرف المستخدم'),
    'name': fields.String(required=True, description='اسم المستخدم'),
    'email': fields.String(required=True, description='البريد الإلكتروني')
})

# بيانات وهمية
users = [
    {'id': 1, 'name': 'أحمد', 'email': 'ahmed@example.com'},
    {'id': 2, 'name': 'سارة', 'email': 'sara@example.com'}
]

@api.route('/users')
class UserList(Resource):
    @api.marshal_list_with(user_model)
    def get(self):
        """جلب جميع المستخدمين"""
        return users
    
    @api.expect(user_model)
    @api.marshal_with(user_model, code=201)
    def post(self):
        """إنشاء مستخدم جديد"""
        data = api.payload
        new_user = {
            'id': len(users) + 1,
            'name': data['name'],
            'email': data['email']
        }
        users.append(new_user)
        return new_user, 201

@api.route('/users/<int:user_id>')
@api.param('user_id', 'معرف المستخدم')
class User(Resource):
    @api.marshal_with(user_model)
    def get(self, user_id):
        """جلب مستخدم محدد"""
        user = next((u for u in users if u['id'] == user_id), None)
        if not user:
            api.abort(404, 'المستخدم غير موجود')
        return user
    
    @api.expect(user_model)
    @api.marshal_with(user_model)
    def put(self, user_id):
        """تحديث مستخدم"""
        user = next((u for u in users if u['id'] == user_id), None)
        if not user:
            api.abort(404, 'المستخدم غير موجود')
        
        data = api.payload
        user['name'] = data.get('name', user['name'])
        user['email'] = data.get('email', user['email'])
        return user
    
    def delete(self, user_id):
        """حذف مستخدم"""
        global users
        user = next((u for u in users if u['id'] == user_id), None)
        if not user:
            api.abort(404, 'المستخدم غير موجود')
        
        users = [u for u in users if u['id'] != user_id]
        return {'message': 'تم الحذف بنجاح'}, 200

if __name__ == '__main__':
    app.run(debug=True)
ميزة رائعة: Flask-RESTx يولد تلقائياً وثائق Swagger UI يمكن الوصول إليها عبر /docs/.

نصائح لبناء APIs احترافية

  • استخدم الإصدارات: أضف رقم الإصدار في المسار مثل /api/v1/users.
  • قم بتوثيق الـ API: استخدم Flask-RESTx أو أدوات توثيق أخرى.
  • استخدم المصادقة: حمِ واجهات الـ API باستخدام JWT أو OAuth2.
  • تعامل مع الأخطاء بشكل جيد: قدم رسائل خطأ واضحة مع رموز الحالة المناسبة.
  • استخدم الترحيل (Pagination): للتعامل مع كميات كبيرة من البيانات.
  • قم بتحديد معدل الطلبات: استخدم Rate Limiting لحماية الـ API من الاستخدام المفرط.
نصيحة اليوم: "API الجيد هو API سهل الاستخدام، موثق جيداً، وآمن."
